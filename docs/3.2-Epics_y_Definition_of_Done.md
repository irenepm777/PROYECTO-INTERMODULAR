# 3.2 Épicas y Definition of Done — SabiApp


## 1. Épicas del proyecto

> Cada épica incluye su descripción de valor, las historias de usuario (US) con su criterio de aceptación clave y su Definition of Done (DoD) específica. La DoD global del proyecto aplica adicionalmente a todos los ítems del backlog (sección 2).

---

### EP-01 · Autenticación y control de acceso multi-rol
**Valor:** Registro, login, recuperación de contraseña y control de acceso seguro para los roles Alumno Sénior y Tutor, con sesión PHP y redirección automática según rol.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-01 | Registro de nuevo usuario | Validación cliente + servidor; contraseña con `password_hash` Argon2id. |
| US-02 | Inicio de sesión | Sesión iniciada en < 2 s; redirección automática al rol correspondiente. |
| US-03 | Cierre de sesión | Sesión destruida completamente; redirección al *login*. |
| US-04 | Recuperación de contraseña | Enlace de un solo uso, caducidad 30 min, enviado al correo. |
| US-05 | Control de acceso por rol | Rutas del panel de tutores devuelven HTTP 403 ante rol incorrecto. |

**DoD — EP-01:**
- [ ] Roles `senior` / `tutor` persistidos correctamente en BD y sesión.
- [ ] Contraseñas almacenadas exclusivamente como hash Argon2id; ninguna en texto plano ni en logs.
- [ ] Protección CSRF en todos los formularios (token de sesión verificado en servidor).
- [ ] Rutas protegidas retornan HTTP 403 ante acceso no autorizado; verificado con tests manuales documentados.
- [ ] Flujo completo probado en Chrome y Firefox.
- [ ] Formularios con `<label>` asociado, navegable con teclado, contraste ≥ 4.5:1 (WCAG 2.2 AA).
- [ ] Código fusionado a `main` exclusivamente mediante PR con ≥ 1 aprobación.
- [ ] Consultas a BD con PDO preparado (sin riesgo de inyección SQL).

### EP-02 · Simulador de Cita Sanitaria (Sandbox)
**Valor:** Entorno seguro para practicar la solicitud de cita médica online sin afectar datos ni sistemas reales, reduciendo el miedo al uso del portal sanitario digital.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-06 | Acceder al simulador de salud | Carga en < 3 s; muestra el primer paso del flujo. |
| US-07 | Pedir cita por especialidad | Flujo de máx. 4 pasos: especialidad → centro → fecha → franja. |
| US-08 | Confirmar o cancelar cita simulada | Pantalla de resumen completo; cancelación posible antes de confirmar. |
| US-09 | Recibir ayuda contextual en cada paso | Icono (?) despliega explicación en lenguaje llano. |
| US-10 | Reiniciar el simulador desde cero | Botón visible en cualquier paso; sin penalización, con confirmación previa. |
| US-11 | Ver historial de prácticas | Número de completados y fecha de la última práctica. |

**DoD — EP-02:**
- [ ] Flujo completo (selección → confirmación → resumen) sin errores en la máquina de estados.
- [ ] Ninguna petición a servicios sanitarios reales; datos ficticios parametrizados en MySQL.
- [ ] Transiciones de pantalla en < 1 s (red throttling 4G en DevTools).
- [ ] Botón de reinicio y ayuda contextual accesibles por teclado y anunciados por lectores de pantalla (NVDA).
- [ ] Objetivos táctiles ≥ 48 × 48 px.
- [ ] Lighthouse ≥ 90 Accesibilidad / ≥ 85 Rendimiento.
- [ ] Progreso registrado en BD y visible en panel de tutores.
- [ ] PR aprobada antes de fusión a `main`.

### EP-03 · Simulador de Bizum / Banca Online (Sandbox)
**Valor:** Práctica de operativa bancaria básica (saldo, movimientos, Bizum) en entorno 100 % simulado, sin riesgo financiero real.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-12 | Acceder al simulador bancario | Pantalla de bienvenida con nombre ficticio y saldo simulado. |
| US-13 | Consultar saldo y movimientos | Saldo simulado + últimos 5 movimientos ficticios. |
| US-14 | Realizar un Bizum simulado | Flujo: teléfono ficticio → importe → concepto → resumen → confirmar (1 clic). |
| US-15 | Recibir alerta de operación inusual | Si importe > 500 € (ficticio), alerta pedagógica con protocolo de verificación real. |
| US-16 | Reiniciar saldo al valor inicial | Botón "Restablecer simulación" vuelve al estado semilla. |
| US-17 | Ver historial de prácticas | Número de transacciones simuladas realizadas. |

**DoD — EP-03:**
- [ ] Sin conexión a APIs bancarias ni pasarelas reales (verificado en DevTools → Network).
- [ ] Flujo de Bizum sin errores en la máquina de estados.
- [ ] Alerta pedagógica (US-15) probada con al menos 1 usuario del público objetivo.
- [ ] Restablecimiento (US-16) restaura exactamente los valores semilla de MySQL.
- [ ] Objetivos táctiles ≥ 48 × 48 px; flujo completable solo con teclado.
- [ ] Lighthouse ≥ 90 Accesibilidad / ≥ 85 Rendimiento.
- [ ] PR aprobada antes de fusión a `main`.

### EP-04 · Módulo de Prevención de Ciberestafas
**Valor:** Entrenamiento reactivo ante *phishing* y *smishing* con retroalimentación pedagógica obligatoria para adquirir criterio crítico frente al fraude digital.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-18 | Iniciar ejercicio de *smishing* | SMS ficticio con remitente anómalo y texto urgente. |
| US-19 | Analizar el mensaje y decidir | Opciones: Ignorar / Bloquear / Pulsar enlace (solo las dos primeras son seguras). |
| US-20 | Recibir retroalimentación inmediata | Pantalla explicativa con 3 indicios visuales que delatan la estafa; obligatoria, no omitible. |
| US-21 | Iniciar ejercicio de *phishing* por correo | Correo ficticio con remitente falsificado y enlace malicioso visible. |
| US-22 | Ver resumen de aciertos y errores | Pantalla de resultados con % de acierto al finalizar todos los ejercicios. |
| US-23 | Reintentar ejercicios fallados | Repetición únicamente de los escenarios resueltos incorrectamente. |

**DoD — EP-04:**
- [ ] ≥ 4 escenarios distintos (mín. 2 *smishing* + 2 *phishing*) parametrizados en BD.
- [ ] Retroalimentación (US-20) no omitible: botón de continuar bloqueado hasta scroll completo o 5 s.
- [ ] Textos revisados por un miembro distinto al autor.
- [ ] Resultados registrados en BD y accesibles desde panel de tutores.
- [ ] Módulo 100 % funcional sin conexión a internet externa (recursos locales).
- [ ] Lighthouse ≥ 90 Accesibilidad.
- [ ] PR aprobada antes de fusión a `main`.

### EP-05 · Panel de Seguimiento para Tutores
**Valor:** Dashboard analítico exclusivo para tutores (familiares o formadores) con progreso real de cada alumno por módulo, identificando los pasos de mayor bloqueo.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-24 | Ver listado de alumnos asignados | Nombre, fecha de último acceso y progreso global (%) por alumno. |
| US-25 | Ver detalle de progreso por módulo | Intentos y estado (completado / en progreso / no iniciado) por simulador. |
| US-26 | Identificar pantallas de bloqueo | Paso concreto donde el alumno abandonó con mayor frecuencia por simulador. |
| US-27 | Asignar un alumno al panel | Añadir alumno por correo registrado; el alumno recibe notificación de vinculación. |
| US-28 | Desasociar a un alumno | Eliminar vinculación sin borrar los datos de progreso del alumno. |

**DoD — EP-05:**
- [ ] Solo rol `tutor` accede al panel; rol `senior` recibe HTTP 403 (tests manuales verificados).
- [ ] Datos actualizados con máx. 5 min de desfase desde la última actividad.
- [ ] Datos del panel coinciden con la tabla de métricas en BD (comprobación cruzada).
- [ ] Vinculación/desvinculación (US-27/28) sin pérdida de datos de progreso.
- [ ] Responsive y usable en tablet (≥ 768 px) sin pérdida de información.
- [ ] Lighthouse ≥ 85 Accesibilidad.
- [ ] PR aprobada antes de fusión a `main`.

### EP-06 · Interfaz Adaptada (UX Sénior)
**Valor:** Sistema de diseño accesible (tipografía *Lexend*, alto contraste, áreas táctiles grandes, lenguaje llano) que permite al alumno sénior usar la plataforma de forma completamente autónoma.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-29 | Visualizar la interfaz con alta legibilidad | *Lexend* ≥ 18 px en body; contraste ≥ 4.5:1 en todos los elementos. |
| US-30 | Navegar con botones y áreas táctiles grandes | Todos los botones ≥ 48 × 48 px (verificado con axe DevTools). |
| US-31 | Recibir instrucciones en lenguaje llano | Sin anglicismos ni tecnicismos; validado por persona ajena al equipo técnico. |
| US-32 | Usar la plataforma en cualquier dispositivo | Responsive sin scrolling horizontal desde 360 px de ancho. |
| US-33 | Ajustar el tamaño de fuente | ≥ 2 tamaños (normal / grande) persistidos en sesión. |

**DoD — EP-06:**
- [ ] Sistema de diseño en Figma (paleta, tipografía, componentes) publicado y actualizado antes de iniciar maquetación.
- [ ] WAVE y axe DevTools sin errores críticos de accesibilidad en ninguna vista.
- [ ] Contraste ≥ 4.5:1 (texto normal) y ≥ 3:1 (texto grande), verificado en Figma y navegador.
- [ ] Lighthouse ≥ 90 Accesibilidad en todas las vistas del alumno sénior.
- [ ] Funciona en 360 px, 768 px y 1280 px sin scrolling horizontal.
- [ ] Test de usabilidad informal con ≥ 1 persona sénior (55+ años) realizado; observaciones en backlog.
- [ ] Sin anglicismos ni tecnicismos en la interfaz de alumno sénior (revisión editorial del equipo).

### EP-07 · Infraestructura, DevOps y Despliegue
**Valor:** Entorno Docker idéntico para los 3 desarrolladores, repositorio GitHub con ramas protegidas y despliegue documentado en VPS con HTTPS obligatorio.

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-34 | Levantar el entorno local con un comando | `docker compose up -d` inicia Nginx, PHP-FPM y MySQL sin errores en los 3 puestos. |
| US-35 | Aplicar migraciones y datos semilla | Script DDL + seeding ejecuta sin errores; BD en estado consistente conocido. |
| US-36 | Desplegar la aplicación en el VPS | Guía de despliegue reproducible en < 30 min por un miembro nuevo. |
| US-37 | Gestionar el versionado de código | Ramas `main` y `dev` protegidas; toda fusión requiere PR + ≥ 1 aprobación. |
| US-38 | Acceder a la aplicación por HTTPS | Producción en HTTPS (Let's Encrypt); HTTP redirige a HTTPS. |

**DoD — EP-07:**
- [ ] `docker-compose.yml` levanta el stack completo sin errores en los 3 equipos (verificado individualmente).
- [ ] `.env.example` documenta todas las variables; ningún secreto en el repositorio.
- [ ] `schema.sql` y `seed.sql` versionados y ejecutables desde el contenedor sin errores.
- [ ] Producción responde en HTTPS; HTTP redirige con código 301.
- [ ] Rama `main` con protección activada en GitHub (sin `push` directo).
- [ ] `README.md` documenta instalación, Docker y acceso a la aplicación.
- [ ] Copia de seguridad MySQL configurada y probada (volcado `mysqldump` ejecutado y restaurado con éxito).

### EP-08 · Módulo de WhatsApp con Microaprendizajes
**Valor:** Itinerario progresivo de 8 lecciones (3–5 min cada una) en 3 niveles que amplían el uso que el sénior ya hace de WhatsApp, desde mensajería básica hasta detección de fraude, todo en un simulador que no accede a funciones reales del dispositivo.

**Itinerario de microaprendizajes:**

| Nivel | ID | Lección | Duración |
| :--- | :--- | :--- | :--- |
| 🟢 Básico | ML-01 | Leer y escribir un mensaje de texto | 3 min |
| 🟢 Básico | ML-02 | Enviar un mensaje de voz (audio) | 3 min |
| 🟢 Básico | ML-03 | Enviar y visualizar una foto | 4 min |
| 🟡 Intermedio | ML-04 | Realizar una llamada de voz | 3 min |
| 🟡 Intermedio | ML-05 | Realizar una videollamada | 4 min |
| 🟡 Intermedio | ML-06 | Gestionar grupos: silenciar y salir | 5 min |
| 🔴 Avanzado | ML-07 | Reconocer un mensaje fraudulento en WhatsApp | 5 min |
| 🔴 Avanzado | ML-08 | Bloquear un contacto desconocido | 4 min |

| ID | Historia de usuario | Criterio de aceptación clave |
| :--- | :--- | :--- |
| US-39 | Acceder al módulo desde el menú principal | Icono reconocible; carga en < 2 s. |
| US-40 | Ver itinerario y progreso | Lista con estado: bloqueado / disponible / completado. |
| US-41 | Practicar escritura de mensajes | Simulador de chat con guía superpuesta; envío ficticio paso a paso. |
| US-42 | Practicar envío de mensaje de voz | Micrófono simulado + animación de grabación; sin acceso al micrófono real. |
| US-43 | Practicar envío de foto | Galería ficticia integrada; envío al chat simulado. |
| US-44 | Simular llamada de voz | Pantalla de llamada (entrante / saliente) con botones de responder, silenciar y colgar. |
| US-45 | Simular videollamada | Interfaz de videollamada con cámara propia ficticia en miniatura. |
| US-46 | Silenciar y salir de un grupo | Secuencia de menú contextual simulado con duración de silencio y confirmación de salida. |
| US-47 | Identificar mensaje de estafa | 3 mensajes (2 legítimos + 1 fraudulento); retroalimentación pedagógica obligatoria. |
| US-48 | Bloquear un contacto desconocido | Guía paso a paso desde el perfil del chat ficticio. |
| US-49 | Recibir insignia al completar un nivel | Pantalla de felicitación + insignia visual persistida en BD. |
| US-50 | Ver progreso de WhatsApp en panel tutor | Lecciones completadas, pendientes y % de avance por alumno. |

**DoD — EP-08:**
- [ ] 8 microaprendizajes (ML-01 a ML-08) accesibles con progresión de desbloqueo correcta (Básico → Intermedio → Avanzado).
- [ ] Ningún microaprendizaje activa funciones reales del dispositivo (micrófono, cámara, galería, contactos); verificado con análisis de permisos en navegador.
- [ ] Simulador de chat usa nombre ficticio («ChatApp» o acordado en equipo) para no infringir marcas registradas.
- [ ] Cada lección completable en ≤ 5 min; comprobado con 3 usuarios de prueba sin asistencia.
- [ ] ML-07 aplica los mismos criterios de retroalimentación obligatoria que EP-04 (botón bloqueado hasta scroll completo o 5 s).
- [ ] Insignias (US-49) persistidas en BD; no se pierden al cerrar sesión.
- [ ] Progreso visible en panel de tutores (US-50).
- [ ] Itinerario completable solo con teclado; elementos del simulador de chat con área táctil ≥ 48 × 48 px.
- [ ] Lighthouse ≥ 90 Accesibilidad en todas las pantallas del módulo.
- [ ] PR aprobada antes de fusión a `main`.

## 2. Definition of Done global del proyecto

> **IMPORTANTE:** Un ítem **no se considera terminado** hasta que cumple **todos** los criterios siguientes sin excepción, independientemente de los criterios específicos de su épica.

| Bloque | Criterio |
| :--- | :--- |
| **Código** | Ejecuta sin errores en el entorno Docker de `main`. |
| **Código** | Fusionado a `main` exclusivamente mediante PR con ≥ 1 aprobación; sin commits directos. |
| **Código** | Sin secretos *hardcodeados*; variables de entorno documentadas en `.env.example`. |
| **Código** | Funciones no triviales comentadas; convención: camelCase (JS) / snake_case (PHP). |
| **Calidad** | Cumple todos los criterios de aceptación de la historia de usuario (prueba manual documentada). |
| **Calidad** | Sin regresiones: funcionalidades anteriores comprobadas en las rutas afectadas. |
| **Calidad** | Errores esperables muestran mensaje comprensible al usuario (nunca *stack trace* expuesto). |
| **Calidad** | Sin datos de prueba (`lorem ipsum`, usuarios de desarrollo) en producción. |
| **Accesibilidad** | Lighthouse ≥ 90 Accesibilidad en vistas del alumno sénior. |
| **Accesibilidad** | Sin errores críticos en axe DevTools en ninguna vista. |
| **Accesibilidad** | Contraste ≥ 4.5:1 (texto normal); objetivos táctiles ≥ 48 × 48 px. |
| **Accesibilidad** | Responsive sin scrolling horizontal en 360 px, 768 px y 1280 px. |
| **Seguridad** | Consultas a BD con PDO preparado (sin inyección SQL). |
| **Seguridad** | Protección CSRF en todos los formularios que modifican estado. |
| **Seguridad** | Rutas protegidas retornan HTTP 403 ante acceso no autorizado. |
| **Seguridad** | Sin cabeceras que expongan versiones de software (`X-Powered-By`, errores PHP). |
| **Entrega** | Historia movida a columna `Done` en el tablero Scrum. |
| **Entrega** | Rama de la feature fusionada a `main` y eliminada del repositorio remoto. |
| **Entrega** | Incremento demostrable en demo de Sprint sin preparación manual extraordinaria. |
